- thread_set_nice()는 nice 변경 후 priority 재계산과 yield 판단을 해야 합니다. reference에 명시되어 있습

  threads/thread.c:512.
- 새 thread의 nice는 parent에서 상속되어야 합니다: docs/reference/pintos-kaist-kr/project1/
  advanced_scheduler.md:25. 현재는 MLFQS에서 항상 0으로 초기화합니다: pintos/threads/thread.c:620.
- recent_cpu는 매초 running, ready, blocked 모든 thread에 대해 재계산되어야 합니다: docs/reference/
  pintos-kaist-kr/project1/advanced_scheduler.md:73. 현재는 ready list와 current thread만 대상입니다:
  pintos/threads/thread.c:960.
- priority도 매 4 tick마다 모든 thread에 대해 재계산되어야 합니다: docs/reference/pintos-kaist-kr/
  project1/advanced_scheduler.md:41. 현재는 ready list와 current thread만 대상입니다: pintos/threads/
  thread.c:902.
- thread_get_recent_cpu()와 thread_get_load_avg()는 100배 값을 nearest integer로 round해야 합니다: docs/
  reference/pintos-kaist-kr/project1/advanced_scheduler.md:91, docs/reference/pintos-kaist-kr/project1/
  advanced_scheduler.md:107. 현재는 truncate입니다: pintos/threads/thread.c:526.

일단 이걸 다 만족하게 코드를 수정하고, 개선 작업을 수행하기.

- recent_cpu 매초 갱신 대상이 아직 “모든 thread”가 아닙니다. 현재는 ready_list, sleep_list, current만 봅
  니다. 하지만 reference는 running/ready/blocked 전부라고 명시합니다. lock/sema/cond에서 blocked 된
  thread는 sleep_list에 없어서 빠집니다. docs/reference/pintos-kaist-kr/project1/
  advanced_scheduler.md:73, pintos/threads/thread.c:966
- priority도 매 4 tick마다 “모든 thread” 재계산 요구인데, 현재는 ready/current만 합니다. sleeping 또는
  synchronization blocked thread의 priority는 stale 상태가 될 수 있습니다. docs/reference/pintos-kaist-
  kr/project1/advanced_scheduler.md:41, pintos/threads/thread.c:907
- idle 실행 중이라고 ready_list가 반드시 비어 있다고 가정하는 건 위험합니다. timer interrupt에서
  threads_wakeup() 이후 MLFQS 갱신을 하므로, idle이 실행 중이던 tick에 sleeping thread가 깨어나면
  ready_list가 비어 있지 않을 수 있습니다. 그런데 현재는 그 상황을 assert로 막습니다. pintos/devices/
  timer.c:130, pintos/threads/thread.c:986
- 1초 경계에서 priority 재계산이 recent_cpu/load_avg 갱신보다 먼저 일어납니다. TIMER_FREQ == 100이고 100
  은 4의 배수라서 같은 tick에 겹치는데, 현재 순서면 최신 recent_cpu를 반영한 priority가 다음 4 tick까지
  밀릴 수 있습니다. pintos/devices/timer.c:132
- recent_cpu 계산이 현재 load_avg 갱신보다 먼저 됩니다. public test 관점에서는 민감한 부분이고, reference
  의 “1초 경계에서 scheduler data가 일관되게 갱신되어야 한다”는 요구와도 잘 맞지 않습니다. docs/
  reference/pintos-kaist-kr/project1/advanced_scheduler.md:17, pintos/threads/thread.c:950

근데 여러 wait_list(sema의 waiter 같은거)를 다 처리할 수 있어야 하는데, 이걸 AI와 이야기함.
