### page 관리 관련 내용 알게된거

Introduction > Managing the Frame Table 에서 나온 내용인데,

> Remove references to the frame from any page table that refers to it. 
> Unless you have implemented sharing, only a single page should refer to a frame at any given time.   
> 
> 해당 프레임에 대한 참조가 있는 모든 페이지 테이블에서 그 참조를 제거해야 합니다. 
> 공유 기능을 구현하지 않는 한, 어떤 순간에도 단 하나의 페이지만이 해당 프레임을 참조해야 합니다.   

이런거 보면 공유 기능(fork, mmap)가 필요하면 하나의 페이지를 여러 reference가 가질 수 있는 형태임을 유추해볼 수 있는걸까?

또, Handling page fault 에서

> If you implement sharing (i.e., Copy-on-Write), 
> the page's data might even already be in a page frame, but not in the page table.
> 
> 만약 공유 기능이 적용된 경우, 
> 해당 페이지의 데이터는 이미 페이지 프레임에 저장되어 있을 수 있지만, 페이지 테이블에는 없을 수 있습니다.

라고 함. 

page frame이 정확히 뭘 의미하는걸까? page 구조체? frame 구조체?

> A frame, sometimes called a physical frame or a page frame, is a continuous region of physical memory.
