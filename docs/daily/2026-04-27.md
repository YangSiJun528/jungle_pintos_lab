1. donations
    - 내가 높여줘야 할 스레드들 리스트
2. wait_on_lock
    - `lock *` 타입
3. d_elem
    - ready, waiter 등의 list와 무관하게 따로 관리되어야 하므로
    - `list_elem` 타입
4. base_priority 값
    - 복구에 필요함. 지금 priority 변수는 너무 외부 의존성이 많아서 따로 파는게 편할 듯?

구현 방식 구상

nested랑 multiple 나눠서 설명

multiple이더라도, 이미 각 락이 nested로 이어져서 앞만 봐도 되므로
nested -> multiple 순으로 구현하면 될 듯? (둘 순서는 다 상관없긴 한데, 내 생각엔 이게 더 자연스러움)

- nested
    - 락 걸 때
        - holder가 있는 경우
            - `wait_on_lock = holder`
            - 내가 holder보다 높은 우선순위를 가지는 경우
            - 해당 holder를 타고 들어가며 나보다 큰 게 나올 때까지
                - 왜냐면 이미 이런 식으로 전파가 되었을 것이므로,
                - 다들 우선순위가 뒤에 있는게 나보다 크면 그 값, 아니라면 본인의 값으로 설정되어있음.
        - holder가 없는 경우
            - 그냥 진행
    - 락 풀 때
        - holder가 있는 경우
            - 이러면 패닉나야지;
        - holder가 없는 경우
            - 해제 후 본인의 priority를 base_priority로 복구
- multiple
    - 락 걸 때
        - holder가 있는 경우
            - donations의 tail에 나를 추가
            - 이 때 list_elem으로 d_elem을 사용
        - holder가 없는 경우
            - 그냥 진행
    - 락 풀 때
        - holder가 있는 경우
            - 이러면 패닉나야지;
        - holder가 없는 경우
            - 그냥 해제 후
            - cur thread의 donations을 순회해서 가장 높은 값을 priority로
            - 대신 base_priority가 더 크면 그걸 채택

### Priority Donation - Nested / Multiple

데드락이 없는 한, DAG 인 형태를 가짐.

애매한거 AI한테 질문해가며 공부   
(Pintos 구현한다는 컨텍스트 없음. 나는 챗봇은 메모리 다 꺼둠.)

- nested = donation이 holder chain을 따라 깊이 전파되는 것
- multiple = 한 스레드가 여러 donation source를 동시에 갖는 것

```text
nested = 깊이
T4 -> T3 -> T2 -> T1
```

한 스레드가 기다리는 lock의 holder가 또 다른 lock을 기다릴 때, donation이 줄줄이 전파됨.

```text
multiple = 너비 / 집합
T2 ┐
T3 ├-> T1
T4 ┘
```

한 스레드 `T1`이 lock 여러 개를 들고 있고, 여러 스레드가 각각 그 lock들을 기다리면 `T1`이 donation을 여러 개 받음.

핵심:

```c
wait_on_lock      // nested 추적용, 보통 1개
donations list    // multiple 관리용, 여러 개
```

즉:

```text
nested  = donation chain
multiple = donation set/list
```

둘 다 동시에 가능함.

예시:

```
T5 -> T3 ┐
T6 -> T4 ├-> T1
T7 ------┘
```

```
T5 -> T3 -> T1  // nested
T6 -> T4 -> T1  // nested
T7 -> T1        // direct donation
```

T1 기준으로는 multiple이고, 각 경로 기준으로는 nested일 수 있음.
