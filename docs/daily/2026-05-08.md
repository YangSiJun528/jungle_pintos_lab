## 용어 매핑

| 용어                       |       분류 | 의미                        | 코드상 대표 이름                    |
| ------------------------ | -------: | ------------------------- | ---------------------------- |
| `virtual address`        |       주소 | CPU 명령어/포인터에 보이는 주소       | `va`, `addr`, `uaddr`        |
| `user virtual address`   |       주소 | 유저 프로세스 주소, `< KERN_BASE` | `upage`, `uaddr`, `page->va` |
| `kernel virtual address` |       주소 | 커널 주소, `>= KERN_BASE`     | `kva`, `kpage`, `frame->kva` |
| `physical address`       |       주소 | 실제 RAM 주소                 | `vtop(kva)` 결과               |
| `page`                   |    단위/객체 | virtual memory의 4KB 단위    | `struct page`                |
| `frame`                  |    단위/객체 | physical memory의 4KB 단위   | `struct frame`               |
| `PML4` / `page table`    | 하드웨어 테이블 | VA → PA 변환용 실제 page table | `thread->pml4`               |
| `SPT`                    | 커널 메타데이터 | page별 VM 상태 관리 테이블        | `thread->spt`                |
| `swap slot`              |   디스크 단위 | evicted page 저장 위치        | anon page swap 정보            |

자료 기준: `Page = virtual memory region`, `Frame = physical memory region`, `Page Table = virtual address를 physical address로 변환하는 자료구조`.

---

## 주소 관계

```text
user VA
  -> PML4 lookup
  -> physical frame
  -> kernel direct-map alias = KERN_BASE + physical address
```

```text
page->va
  = user virtual address

frame->kva
  = kernel virtual address
  = physical frame을 커널에서 접근하기 위한 주소

vtop(frame->kva)
  = physical address
```

---

## PML4 역할

| 항목         | 내용                                                                                 |
| ---------- | ---------------------------------------------------------------------------------- |
| 성격         | x86-64 CPU/MMU가 실제로 해석하는 page table                                                |
| 소유         | 프로세스별 `struct thread->pml4`                                                        |
| 관리 주체      | 커널                                                                                 |
| 사용 주체      | CPU/MMU                                                                            |
| 저장 정보      | present mapping, writable bit, user/kernel bit, accessed/dirty bit 등               |
| 표현         | `user VA -> physical frame`                                                        |
| Pintos API | `pml4_create`, `pml4_set_page`, `pml4_get_page`, `pml4_clear_page`, `pml4_destroy` |
| 디버깅 의미     | “현재 CPU가 접근 가능한가?” 확인                                                              |

```c
pml4_set_page(t->pml4, upage, kpage, writable);
```

```text
upage = user virtual page
kpage = frame을 가리키는 kernel virtual address
PTE 내부 = physical frame address + flags
```

---

## SPT 역할

| 항목         | 내용                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 성격         | Pintos VM용 커널 메타데이터                                                                                |
| 소유         | 프로세스별                                                                                              |
| 관리 주체      | 커널                                                                                                 |
| 사용 주체      | 커널 page fault handler                                                                              |
| 저장 정보      | page type, writable, frame 위치, swap 위치, file 위치, lazy-load aux 등                                   |
| 표현         | `user VA -> struct page`                                                                           |
| Pintos API | `spt_find_page`, `spt_insert_page`, `supplemental_page_table_copy`, `supplemental_page_table_kill` |
| 디버깅 의미     | “이 VA가 논리적으로 valid한가?” 확인                                                                          |

자료 기준: SPT는 page table을 보완하는 per-page 추가 정보 저장소이고, page fault 시 “데이터가 어디에 있어야 하는지” 찾는 용도 및 process 종료 시 resource free 판단 용도.

---

## PML4 vs SPT

| 상황                         |     SPT |       PML4 |
| -------------------------- | ------: | ---------: |
| executable lazy page 등록 직후 |      있음 |         없음 |
| mmap 직후                    |      있음 |         없음 |
| 첫 접근 전 lazy page           |      있음 |         없음 |
| page fault 처리 후 claim 성공   |      있음 |         있음 |
| memory resident page       |      있음 |         있음 |
| swapped-out page           |      있음 |         없음 |
| evicted file-backed page   |      있음 |         없음 |
| invalid address            |      없음 |         없음 |
| process exit 중             | kill 대상 | destroy 대상 |

---

## 동작 흐름

```text
load / mmap / stack setup
  -> SPT에 struct page 등록
  -> PML4에는 아직 없을 수 있음
```

```text
user가 VA 접근
  -> PML4 lookup 실패
  -> page fault
  -> SPT lookup
  -> valid page면 frame 할당
  -> swap_in / lazy_load
  -> pml4_set_page()
  -> user instruction 재시도
```

```text
eviction / swap_out
  -> victim frame 선택
  -> 필요 시 swap/file write-back
  -> PML4 mapping 제거
  -> SPT page metadata 유지
```

자료 기준: lazy loading에서는 `struct page` 할당이 곧 physical frame 할당을 의미하지 않고, 실제 physical frame은 나중에 할당됨.

## 구현 기준 체크리스트

| 질문                      | 볼 곳                                                      |
| ----------------------- | -------------------------------------------------------- |
| 이 주소가 유저 주소인가?          | `is_user_vaddr(addr)`                                    |
| 이 VA가 논리적으로 valid한가?    | `spt_find_page(&t->spt, pg_round_down(addr))`            |
| 이 VA가 현재 매핑되어 있나?       | `pml4_get_page(t->pml4, addr)`                           |
| 이 page가 frame을 갖고 있나?   | `page->frame != NULL`                                    |
| frame을 커널이 만질 주소는?      | `page->frame->kva`                                       |
| PML4에 user mapping 추가는? | `pml4_set_page(t->pml4, page->va, frame->kva, writable)` |
| swap/file 위치 정보는?       | `struct page` 내부 type별 필드                                |
| eviction 대상 관리는?        | frame table                                              |
| swap slot 관리는?          | swap table                                               |

---

## 한 줄 구분

```text
SPT = OS가 인정하는 논리적 가상 메모리 상태
PML4 = CPU가 실제로 번역 가능한 현재 매핑 상태
Frame table = 실제 물리 프레임 점유 상태
Swap table = 디스크 swap slot 점유 상태
```
