### Memory Mapping Files 하기

#### 공부부터

일단 그냥 매핑은 되게 쉬울수도 있을거 같음.

왜냐면 프로세스 간 통신 같은 거나 COW가 필수 요구사항이 아니기 때문임.

> If two or more processes map the same file,
> there is no requirement that they see consistent data.
>
> 두 개 이상의 프로세스가 동일한 파일을 매핑하더라도,
> 그들이 일관된 데이터를 보아야 한다는 요구는 없습니다.

일단은 고려하지 않는게 정신건강에 좋을 듯?

근데 그러면 두 프로세스가 동시에 쓰거나 읽거나 할 때 충돌이 날 수도 있을거 같은데
(락 걸어서 내부가 많이 꼬이지는 않겠지만, - 데드락은 될 수도?)

이런 동시성과 관련한 경우는 어떻게 처리할지는 좀 생각해봐야 할 거 같음.
-> 생각해보니 싱글코어 프로세스라 괜찮나?

근데 시스템 콜 도중에 스위칭이 될 수도 있을 거 같은데?

근데 그러면 락 걸고 있을꺼라 어차피 수정 못함.

그래서 정리하면?

"동시에 파일을 읽거나 쓴다"는 가정이 잘못된 이유는

특정 파일에 접근 시 락이 걸려서 해당 프로세스를 제외한 나머지는 파일에 읽거나 쓸 수 없다.   
(`syscall.c` 참고)

이거 때문임.

그 외에 멀티코어는 다르지 않나 싶은데, 지금은 시스템 콜 처리 코드에서 전역적으로 막고 있어서 괜찮음.

아마 파일시스템 들어가면 파일 자체적으로 락이 구현되는거 같던데,   
그러면 여러 프로세스가 접근하거나 파일마다 별도의 락을 가지고 있으므로.

데드락 문제가 생길 수 있을 듯?

락이 있으면 멀티코어에서도 괜찮지 않을까 싶긴 함.
근데 mmap 같은 경우는 메모리랑 파일이랑 연결되어 있어서 다를수도.

#### 위 고민이 의미 없었을지도? - 항상 깃북을 읽읍시다...

- 시스템 콜
    - mmap
    - munmap
- 구현할 함수
    - do_mmap
    - do_munmap
    - 이걸 시스템 콜에서 가져다 씀
- mmap call 시, 유효성 검사 조건
    - length가 0이면 실패 - (다른 콜은 성공했던거 같은데 이거는)
    - fd가 0,1 인 경우
    - file이 유효하지 않은 경우 (size가 0, 인자 자체는 fd로 넘어옴)
    - addr이 NULL 인 경우 (자동 주소 할당 없음)
    - addr이 페이지 경계가 아님 - (아마 파일이랑 묶어야 해서? 기존에는 없던 조건)
    - addr..(addr+size) 범위 사이의 페이지가 하나라도 유효하지 않은 경우
        - 탐색 로직은 기존 버퍼 검사 참고해서 순회하면 될 듯? 

- mmap 시 동작
  - vm_alloc_page_with_initializer or vm_alloc_page 을 사용해 메모리 할당

- 프로세스 exit 시 or unmmap 시 
  - 쓴 파일 메모리 부분은 디스크에 쓰기
