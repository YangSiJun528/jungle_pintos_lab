#### 결과 보기

> 일반적인 실제 OS는 언제든지 프로세스를 중단시켜 스택의 데이터를 수정하는 “signal”을 전달할 수 있으므로, 
> 사용자 프로그램이 스택 포인터 아래의 스택에 기록하면 버그가 있는 것입니다. 
> 그러나 x86-64 PUSH 명령어는 스택 포인터를 조정하기 전에 접근 권한을 확인하므로, 스택 포인터보다 8바이트 아래에서 페이지 폴트를 일으킬 수 있습니다.

```
[DEG] r=thrd tid= 3 p4=0x800424a000 k=note   fn=vm_try_handl vals={addr=0x4747ee78 sp=0x4747ee80 rdsp=0x4747e000 rusp=0x4747f000} 
```

근데 엄 그러면 폴트가 난거면 그걸 page로 관리되고 있어야 하는거 아닌가?

근데 지금 업 다운하면 저 부분이 페이지로 관리되지 않는 영역인거 같은데?

글거 또 뭔 커널에서 폴트나는 경우도 고려해야 한다는데 일단 이건 모르겠고 넘기기

`0x4747ee80 - 8 = 0x4747ee78` 이거 구글 계산기 돌리면 그렇게 나오는데 왜 8이 늘어난거지?

아 16진수니까 그렇겠네 맞네 8늘려야 16되서 자리수 증가구나

`0x4747f000 - 0x4747ee80 = 0x180` 이라는데 왜 그렇지? 그럼 스택 증가하는 케이스가 아니지 않나?

그러면 저걸 (addr에 8 더하면 sp와 같은 경우) 정상적인 요청이라고 치고 넘기기.
