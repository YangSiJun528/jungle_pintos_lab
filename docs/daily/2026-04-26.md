### 페어프로그래밍 개발


이거 생각보다 코드 분리가 잘 되어있네, 내부 함수면 static이고, 아니면 아닌거고.

특정 내부 변수를 수정하는 작업은 다 특정 c 코드에 넣어두고 함수만 제공하고...

sleep_entry 만들어서 할라는데, 이러면 생에주기 관리가 더 필요해져서 그냥 thread에 넣음.

페어프로그래밍으로 개발, sleep_list sort하는건 필요없었고, 그래서 그냥 간단하게 함.

테스트 돌려서 잘 되는거까지 확인함.

`list.h/.c`보고 사용법 익히는건 AI 도움좀 받음. 코드 구현을 맡긴것도 아니고 그냥 유용한 패턴 몇가지 물어봤을 뿐임.

생각보다 인터럽트나, 함수 가져다 쓸지 말지 고려하는게 좀 의사코드랑 달랐음.

결국에 1:1 대응이 될 정도가 아닌 의사코드가 아닌 이상, 큰 그림 잡고 구현 들어가는게 맞는듯?

자료 보면 순차적으로 작업 가능하게 되어있기도 해서...

### 개인 레포 분리

worktree 써도, fork해서 개인/협업을 한 레포로 병행하는게 생각보다 귀찮은 일임. upstream이랑 동기화해줘야 해서.
