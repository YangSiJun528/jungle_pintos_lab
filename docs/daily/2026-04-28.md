### Priority Donation - Nested / Multiple 복습

이해 안가던거 AI 피드백 받으며 정리.

- nested: 새 donation이 들어올 때 체인을 따라 위로 전파해야 함.
    - 이건 추가할 때만 필요하므로 lock_acquire에만 있으면 됨.
    - 왜냐면 어차피 쭉 따라가면 lock holder 체인의 끝(편의상 root)까지 영향을 받음.
- multiple: lock release나 base priority 변경 때 남은 donor들 중 max로 복구해야 함.
    - lock release의 경우 donors가 바뀌어서,
    - base priority 변경은 `max(max_priority(donors), base_priority)` 결과가 바뀔 수 있게 되었으니까?
    - 둘 다 결론적으론 root의 `max(max_priority(donors), base_priority)` 결과가 바뀔 수 있으면 되는거?
- 둘은 섞여서 사용됨..
    - 어떤 노드가 nested chain의 중간이면서 multiple donors를 동시에 가질 수 있음.
    - (dead-lock이 아닌 이상) 트리나 DAG를 생각하면 됨.

### MLFQS 공부

MLFQS는 보니까 그냥 우선순위를 구하는 공식이 있고, 그거에 따라서 우선순위가 바뀌는데,

cpu bound면 낮추고, io bound면 높히네 왜냐면 짦게 수행되고 바로 대기하니까 먼저 해주고,
그런 io bound가 끝나고 남은 시간에 cpu bound를 하는거지.

정확히는 특정 연산이 bound 되는거 까지는 판단 안하고, 그냥 block 시간 정도로 판별하는거임.

실제로는 저렇게 극단적인 애들 말고 중간에 적절히 쓰는게 있겠지만, 뭐 아무튼 핵심 개념은 이거같은데.

이러면 기존에 스레드의 실행 성향에 따라 적절한 효율적인 스케쥴링을 하는 느낌인거고.

#### 고정소수점 만들기

이게 17.14인데

부호가 1, 16이 정수, 14가 소수 부분임.

정수는 2^16(65536) 표현 가능

소수는 2^14(1/16384) 단위로 표현 가능함.

값을 `{값}/16384` 형태로 치는거라.  
0 제외하면 `1/16384` ~ `16383/16384` 까지 표현 가능한거.

(10^-5 수준이니까) 소수점 아래 약 4~5자리 정도 정확도를 가짐.

강의 자료를 보면,

> 다음 table(표)은 fixed-point arithmetic operation을 C에서 구현하는 방법을 요약합니다.
> 표에서 `x`와 `y`는 fixed-point number,
> `n`은 integer, fixed-point number는 `p + q = 31`인 signed `p.q` format이고,
> `f`는 `1 << q`입니다.

이러고 테이블이 나오는데, 이거 그대로 구현하면 될 듯?

우리는 p가 16이고, q는 14임. f는 곳 `1 << 14`로 비트시프트한거임.   
(외냐면 15번째 비트가 정수부 제일 낮은자리수니까.)
