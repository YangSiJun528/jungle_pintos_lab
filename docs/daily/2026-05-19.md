# VM 주차 내용 정리

## VM과 Swap 개념 이해하기

어제 정리한 page table/pte, spt 역할 부분은 생략하고 나머지 전체적은 흐름 부분

swap in은 “page 내용을 새 physical frame으로 가져오는 작업”
swap out은 “현재 physical frame에 올라와 있는 page 내용을 다른 page가 쓸 수 있게 비우는 작업”

### 호출도 흐름

[docs/ai/036_페이징이_이루어지는_과정.md](/docs/ai/036_페이징이_이루어지는_과정.md) 을 참고하면 더 구체적으로 나옴.

```text
page fault
  -> page_fault()
  -> vm_try_handle_fault()
      -> spt_find_page()
      -> 필요하면 vm_stack_growth()
  -> vm_do_claim_page()
  -> vm_get_frame()
      -> palloc_get_page(PAL_USER)
      -> 실패하면 vm_evict_frame()
          -> vm_get_victim()
          -> swap_out(page)
          -> pml4_clear_page()
  -> pml4_set_page()
  -> swap_in(page, frame->kva)
      -> VM_UNINIT이면 uninit_initialize()
      -> 이미 초기화된 page면 backing store에서 복구
  -> user program 재개
```

#### 단어 의미

- claim: 청구하다
- evict: 쫓아내다
- victim: 희생양

### SPT와 Swap

(이쪽 파트는 뇌피셜임)

처음 봤을 때, aux나 메타데이터는 왜 따로 저장하지 않는지 궁금했는데,

이러한 메타데이터는 매우 적은 용량이라서 굳이 디스크에 저장하거나 할 필요는 없다.

즉, SPT는 Swap 대상이 아니다, 한 frame은 4kb인데 반해서,
메타데이터는 그보다 훨신 작은 양이고, 이걸 저장하는 효율 대비 추가되는 처리량이 더 클 것이다.

### 각 타입 별 Swap 정리

각 함수의 역할은 대충 알겠으니, 이걸 어떻게 타입별로 구현했는지 분석하기.

- 공통
    - swap in 전/후: - `vm_do_claim_page()` 에서
        - page, frame, owner thread 등의 메타 정보를 저장하고, frame list에 추가한다.
        - 에러가 난 경우 이러한 자원을 해제하고 실패 처리한다.
    - swap out 전/후: - `vm_evict_frame()` 에서
        - pml4에서 해당 frame을 clear 한다. (이래야만 pml4에 새 공간이 할당된다.)
            - 값을 0으로 채워서 위험한 일이 발생하지 않게 한다.
        - SPT에서 page와 frame의 메타 정보에 해당되는 값을 비운다.

- uninit
    - swap in: 생성 시 건네준 init 함수를 호출하고, 각 타입에 맞는 initializer를 호출함.
        - initializer는 각 타입에 맞는 하위 page 구현체를 기본 값으로 초기화하는 역할이다.
        - 인자로 넘긴 init 함수는 aux과 같은 추가 데이터를 받아 정보를 할당받는 역할이다.
        - swap out: 없다. frame 연결이 없으니 비워줄 것도 없다.
- anon
    - swap in: 
      - 저장된 내용을 새로 전달받은 물리 메모리에 쓴다.
      - swap disk에서 데이터가 저장된 위치는 SPT에 저장된 swap_slot를 사용해 swap_table(비트맵)에서 찾는다.   
    - swap out: 
      - swap disk에서 데이터를 불러와, 새 frame의 내용을 저장한다.
      - swap_table(비트맵)의 `bitmap_scan_and_flip()` 연산을 통해 swap disk의 할당 가능한 공간을 찾는다.
- file_backed
    - swap in: 
      - 만약 더티 페이지인 된 경우 원본 파일에 쓰고, 아니면 바로 종료한다.
    - swap out:
      - 로드 시 SPT에 저장된 파일의 오프셋 기반으로 새 frame의 내용을 채운다.

swap table은 비트맵 기반으로 swap 가능 여부를 효율적으로 표시한다.
frame table은 list에 FIFO 규칙을 지켜서 작성하므로, 가장 오래전에 추가되었던 프레임을 제거하도록 한다.

비트맵 동작의 경우 다음 자료를 참고한다. [docs/ai/037_비트맵_함수_동작.md](/docs/ai/037_비트맵_함수_동작.md)
