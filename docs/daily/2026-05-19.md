# VM 주차 내용 정리

어제 정리한 page table/pte, spt 역할 부분은 생략하고 나머지 전체적은 흐름 부분

### 페이징이 이루어지는 과정

swap in은 “page 내용을 새 physical frame으로 가져오는 작업”
swap out은 “현재 physical frame에 올라와 있는 page 내용을 다른 page가 쓸 수 있게 비우는 작업”

참고: `docs/ai/035_swap_in_out_구현_흐름.md`

#### 각 함수의 동작

#### 전체 흐름

```mermaid
flowchart TD
    A["page_fault(): page fault 진입"] --> B["vm_try_handle_fault(): VM에서 복구 가능한 fault인지 판단"]
    B --> C{"복구 가능?"}
    C -- "yes" --> D["vm_do_claim_page(): page를 frame에 올림"]
    D --> E["user program 재개"]
    C -- "no" --> F["process 종료 또는 kernel fault 처리"]
```

#### `vm_try_handle_fault()`

```mermaid
flowchart TD
    A["vm_try_handle_fault()"] --> B["spt_find_page(): fault 주소의 page metadata 조회"]
    B --> C{"SPT에 page가 있음?"}
    C -- "no" --> D["validate_stack_area(): stack growth 가능성 확인"]
    D --> E{"stack growth 가능?"}
    E -- "yes" --> F["vm_stack_growth(): stack page 생성 및 claim"]
    E -- "no" --> G["false 반환"]
    C -- "yes" --> H{"권한/상태가 유효?"}
    H -- "no" --> G
    H -- "yes" --> I["vm_do_claim_page(): page fault 복구 진행"]
```

#### `vm_do_claim_page()`

```mermaid
flowchart TD
    A["vm_do_claim_page()"] --> B["vm_get_frame(): 사용할 physical frame 확보"]
    B --> C["page-frame 연결"]
    C --> D["pml4_set_page(): user VA와 frame 매핑"]
    D --> E{"mapping 성공?"}
    E -- "no" --> F["실패 정리 후 false 반환"]
    E -- "yes" --> G["swap_in(): page 내용을 frame에 준비"]
    G --> H{"swap_in 성공?"}
    H -- "no" --> I["pml4_clear_page(): 만든 mapping 제거"]
    I --> F
    H -- "yes" --> J["frame_table 등록"]
    J --> K["true 반환"]
```

#### `vm_get_frame()`

```mermaid
flowchart TD
    A["vm_get_frame()"] --> B["palloc_get_page(): user pool에서 새 frame 요청"]
    B --> C{"새 frame 확보 성공?"}
    C -- "yes" --> D["새 frame 반환"]
    C -- "no" --> E["vm_evict_frame(): 기존 frame 하나를 비워서 재사용"]
    E --> F["evicted frame 반환"]
```

#### frame 부족 시 eviction 흐름

```mermaid
flowchart TD
    A["vm_evict_frame()"] --> B["vm_get_victim(): evict할 frame 선택"]
    B --> C["swap_out(): victim page 내용을 backing store에 저장"]
    C --> D["pml4_clear_page(): victim page mapping 제거"]
    D --> E["page-frame 연결 해제"]
    E --> F["victim frame 반환"]
```

#### `swap_in()`의 큰 의미

```mermaid
flowchart TD
    A["swap_in()"] --> B{"page가 아직 VM_UNINIT인가?"}
    B -- "yes" --> C["uninit_initialize(): 실제 page type으로 초기화"]
    C --> D["lazy load callback: 필요한 내용을 처음 적재"]
    B -- "no" --> E["page operation: backing store에서 내용 복구"]
    D --> F["frame에 page 내용 준비 완료"]
    E --> F
```

`VM_UNINIT`일 때의 `swap_in()`은 이름과 달리 disk swap 복구가 아니다. 첫 fault에서 page를 실제 type으로 바꾸고 lazy loading을 실행하는 흐름이다.

#### `swap_out()`의 큰 의미

```mermaid
flowchart TD
    A["swap_out()"] --> B["page operation: page type에 맞는 저장 방식 선택"]
    B --> C["backing store에 page 내용 보존"]
    C --> D["eviction이 frame을 비울 수 있는 상태가 됨"]
```

타입별 구현체의 세부 동작은 여기서 중요하지 않다. 핵심은 `swap_out()`이 frame을 비우기 전에 page 내용을 잃지 않도록 보존한다는 점이다.

#### 다시 접근할 때의 흐름

```mermaid
flowchart TD
    A["user가 evicted page에 다시 접근"] --> B["page_fault()"]
    B --> C["vm_try_handle_fault(): SPT에서 page metadata 발견"]
    C --> D["vm_do_claim_page(): 새 frame 확보"]
    D --> E["swap_in(): backing store에서 내용 복구"]
    E --> F["user program 재개"]
```
