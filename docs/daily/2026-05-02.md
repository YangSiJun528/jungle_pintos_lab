> 근거는 다음과 같다.
> 1. 커널이 `KERN_BASE` 이상 영역에 접근하다 page fault가 나면, 이는 정상 상황이 아니라 커널 버그로 보는 것이 맞다.
> 2. `KERN_BASE` 아래 영역에 접근하는 경우는 syscall 인자로 받은 유저 메모리를 읽거나 쓰는 상황이므로, 이를 항상 `get_user/put_user`로 처리하도록 통일할 수 있다.
> 3. 더 안전하게는 **커널에서 발생한 page fault 중 `KERN_BASE` 아래 주소 접근은 전부 `get_user/put_user`에서 발생한 것으로 간주**해도 된다.
> 4. `done_get`, `done_put`의 정확한 주소를 비교하는 방식은 컴파일마다 주소가 바뀔 수 있어 권장하지 않는다.

#### 현재 구조 크게 정리

근데 일단 지금 pintos에선 heap이 없는거 같으니 고려하지 않고,

page 단위로 제공하는거 만 있는거 같은데, 실제론 이 방식은 mmap랑 유사한거 같음.

커널도 실제 메모리에 접근이 불가능함 (CPU가 함).

따라서 커널도 kernel virtual address를 가지는데, 이를 pintos에서 kpage라고 한다.

그리고 그 영역을 커널이 데이터를 읽고 쓰는데 쓸 수도 있지만, 유저레벨에서 필요한 경우

유저 레벨에서 page를 요청 시 vtable에 커널의 가상 주소와 user virtual address range(upage)를 매핑한다.   
(커널에서 쓰는 데이터가 있는걸 주는건 아니고 유저 레벨로 제공하기 위해 관리되는 영역에서 빼서 주게 구현)

그 경우 유저 레벨에서 접근하고 사용할 수 있게 된다.

단, 시스템 콜 등으로 작업을 할 때 넘겨주면,
커널 영역에서도 동일한 physical frame을 바라보는 가상 주소 kpage를 가지므로, 커널에서 접근하고 코드를 수정할 수 있다.

실제에선 mmap가 이 동작이랑 좀 비슷한 듯? - https://linux-kernel-labs.github.io/refs/pull/190/merge/labs/memory_mapping.html
