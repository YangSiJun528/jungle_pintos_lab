이 map은 “어디에 놓여 있는가”보다 “누가 어떤 주소로 접근하는가”를 보여 주는 자료입니다. kernel direct mapping과 user page table mapping을 분리해서 보세요.

Memory map

가운데는 현재 process의 virtual address space입니다. 위쪽 kernel 영역은 모든 process에서 공통이고, 아래쪽 user 영역은 process마다 다릅니다. 오른쪽은 실제 RAM입니다.

solid arrow = kernel direct map, dashed arrow = user page table map

kernel은 physical address를 직접 포인터처럼 쓰지 않고, `KERN_BASE + physical address`라는 kernel virtual address로 RAM을 봅니다.

user pool은 physical memory의 일부이며, 그 frame들도 같은 kernel direct map으로 접근됩니다.

user virtual address는 process마다 독립적입니다. user page는 PML4 page table entry를 거쳐 user pool의 physical frame에 연결됩니다.

같은 `upage`라도 process마다 다른 frame을 가리킬 수 있습니다.

RAM frame이 복사되는 것이 아닙니다. 하나의 physical frame이 user virtual address와 `KERN_BASE + paddr` 양쪽 virtual address에 매핑될 수 있다는 뜻입니다.

kernel virtual memory user virtual memory physical memory unmapped / reserved virtual area 실선 화살표 = kernel direct mapping 점선 화살표 = user page table mapping 짧은 선 = 특정 주소 지점 {brace = 주소 범위

1. kernel은 오른쪽 RAM을 위쪽 kernel 주소로 본다

실선은 physical memory가 kernel virtual memory에 고정 offset으로 비친다는 뜻입니다.

2. user는 아래쪽 user 주소만 본다

`KERN_BASE` 위쪽은 같은 process page table 안에 있어도 user mode에서 접근할 수 없습니다.

3. user page는 dashed path로 frame에 연결된다

user BSS, code, stack은 user pool을 직접 보는 것이 아니라 PML4 mapping을 통해 frame에 도달합니다.

4. 왼쪽 주소는 representative value다

`KERN_BASE`, `USER_STACK`, `0x400000`은 Pintos 기준값이고, `paddr`, `upage`는 실행 중 선택되는 주소 변수입니다.

1

kernel direct mapping은 kernel이 physical memory를 다루는 창이다

Pintos는 physical memory를 `KERN_BASE` 위 kernel virtual address에 일대일로 매핑합니다. 그래서 kernel은 physical address를 포인터처럼 직접 쓰지 않고, kernel virtual address로 같은 frame을 접근합니다.

kernel virtual address = KERN_BASE + physical address physical address = kernel virtual address - KERN_BASE

map의 실선은 이 관계를 나타냅니다. user pool에 속한 physical frame도 kernel이 볼 때는 kernel direct map을 통해 접근됩니다.

1a

`KERN_BASE + physical address`는 매핑 정보를 저장한다는 뜻이 아니다

`KERN_BASE + paddr`는 kernel이 사용할 virtual address를 계산하는 식입니다. 매핑 정보 자체는 page table entry에 저장되고, MMU가 그 page table을 보고 virtual address를 physical address로 변환합니다.

paddr = 0x1234 kaddr = KERN_BASE + paddr kernel이 *(uint8_t *) kaddr 를 읽으면 MMU가 kaddr -> physical 0x1234 로 변환한다

따라서 “VM 위에 뭔가를 띄운다”기보다는, kernel virtual address라는 창을 통해 실제 physical frame을 읽고 쓰는 것입니다.

2

kernel pool과 user pool은 physical frame의 출처를 나누는 말이다

`kernel pool`은 kernel 내부 자료구조, buffer, page table 같은 kernel 용도 frame을 얻는 곳입니다. `user pool`은 user page에 붙일 frame을 얻는 곳입니다.

둘 다 physical memory 안의 pool입니다. user pool이라는 이름 때문에 user program이 그 주소를 직접 본다고 이해하면 안 됩니다.

3

KERN_BASE는 단순한 선이 아니라 permission wall이다

user virtual memory는 `KERN_BASE` 아래입니다. user program이 `KERN_BASE` 위 kernel virtual address를 접근하려고 하면 page fault가 발생합니다.

반대로 kernel mode는 kernel virtual memory에 접근할 수 있고, 현재 실행 중인 process의 user virtual memory도 필요하면 접근할 수 있습니다.

4

user BSS, data, stack은 process별 virtual memory다

가운데 아래의 user BSS, initialized data, code, stack은 user program이 보는 영역입니다. 같은 virtual address라도 process A와 process B가 서로 다른 physical frame에 매핑될 수 있습니다.

Process A: user virtual 0x500000 -> physical frame A Process B: user virtual 0x500000 -> physical frame B

이 독립성이 process isolation의 핵심입니다.

5

user page는 page table을 통해 physical frame과 만난다

점선은 user virtual page가 PML4 page table entry를 통해 user pool의 physical frame에 연결되는 경로입니다. user program은 physical address나 user pool 주소를 직접 알 필요가 없습니다.

1. kernel이 user pool에서 frame 확보 2. kernel virtual address로 frame 초기화 3. PML4에 upage -> frame mapping 설치 4. user program은 upage로 접근
5a

direct mapping은 virtual address range를 더 쓰지만 physical memory를 두 배로 쓰지는 않는다

같은 physical frame이 user virtual address와 kernel virtual address 양쪽에 보일 수 있습니다. 이것은 virtual mapping이 두 개라는 뜻이지, RAM frame이 두 개 복사된다는 뜻은 아닙니다.

user virtual upage ───────┐ ├─ same physical frame kernel virtual KERN_BASE+p ┘

대신 OS는 virtual address space 일부를 kernel용으로 예약합니다. 그래서 user에게 제공되는 virtual address 범위는 하드웨어가 이론적으로 표현할 수 있는 전체 범위보다 작게 정해질 수 있습니다. Pintos는 `KERN_BASE = 0x8004000000`을 경계로 그런 선택을 합니다.

6

왼쪽 thread page는 user stack과 다른 kernel 구조다

왼쪽의 `struct thread`, kernel stack, interrupt frame은 thread를 실행하고 관리하기 위한 kernel 쪽 memory입니다. user stack은 가운데 아래 user virtual memory 안에 있는 별도 영역입니다.

즉 “stack”이라는 이름이 같아도 user stack과 kernel stack은 접근 권한, 용도, 위치가 다릅니다.

이 map의 핵심 결론

  • physical memory는 오른쪽에 있고, virtual address space는 가운데에 있습니다.
  • kernel virtual memory는 physical memory를 고정 offset으로 볼 수 있습니다.
  • user virtual memory는 process마다 다르고, PML4 mapping을 통해 physical frame에 연결됩니다.
  • user pool은 user가 직접 접근하는 주소 공간이 아니라 user page용 frame의 출처입니다.
  • user BSS는 user가 접근 가능하지만, kernel BSS는 user가 접근할 수 없습니다.
