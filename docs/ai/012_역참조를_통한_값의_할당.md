# 역참조(Dereferencing)를 통한 값의 할당

이 문서는 C에서 "주소값을 담은 변수에 대입하는 것"과 "그 주소가
가리키는 메모리 위치에 대입하는 것"의 차이를 정리한다.

Pintos `argument passing`처럼 `rsp` 같은 주소값을 다룰 때 이 둘이
쉽게 섞인다. 핵심은 단순한 주소 연산이 아니라, 대입문의 왼쪽이
어떤 저장 위치를 가리키는지다.

## 한 줄 결론

`addr = value`는 `addr`이라는 변수 자체의 값을 바꾸는 것이다.

`*(타입 *) addr = value`는 `addr`이 가리키는 메모리를 `타입`의 저장
공간으로 해석한 뒤, 그 위치에 `value`를 저장하는 것이다.

## 대입문의 왼쪽은 저장 위치다

C에서 대입문은 다음처럼 읽을 수 있다.

```c
left = right;
```

여기서 `left`는 값을 저장할 수 있는 위치여야 한다. 예를 들어 일반
변수는 그 자체가 저장 위치다.

```c
int x;

x = 10;
```

이 코드는 `x`라는 변수의 저장 공간에 `10`을 넣는다.

포인터를 통해 다른 메모리 위치에 값을 넣고 싶을 때는 `*` 연산자로
역참조한다.

```c
int x;
int *p = &x;

*p = 10;
```

여기서 `p`는 주소를 담은 변수이고, `*p`는 `p`가 가리키는 메모리
위치다. 그래서 `*p = 10`은 `p` 자체를 바꾸는 것이 아니라 `x`의
저장 공간에 `10`을 넣는다.

## 주소값 변수와 가리키는 메모리

주소값을 숫자로 들고 있는 경우를 생각해 보자.

```text
주소값 변수:
  addr = 0x1000

메모리:
  0x1000: ?
```

`addr`와 `0x1000` 위치의 메모리는 같은 것이 아니다.

| 표현 | 의미 |
|---|---|
| `addr` | 주소값을 담은 변수 |
| `(타입 *) addr` | `addr` 값을 `타입 *` 포인터로 해석한 값 |
| `*(타입 *) addr` | 그 포인터가 가리키는 메모리 위치 |

따라서 다음 코드는 메모리 `0x1000`에 값을 쓰는 코드가 아니다.

```c
addr = 0;
```

이 코드는 `addr` 변수 안의 주소값을 `0`으로 바꾼다.

메모리 `0x1000` 위치에 값을 쓰려면, 그 주소를 포인터로 해석하고
역참조한 표현식을 대입문의 왼쪽에 둬야 한다.

```c
*(uintptr_t *) addr = value;
```

이때 `addr` 자체의 값은 바뀌지 않는다. 바뀌는 것은 `addr`이
가리키는 메모리 위치의 내용이다.

## 왜 타입 캐스팅이 필요한가

`rsp` 같은 값이 `uintptr_t`처럼 정수형 주소값으로 저장되어 있다면,
컴파일러 입장에서는 그것이 어떤 타입의 객체를 가리키는지 알 수
없다.

```c
uintptr_t addr;
```

이런 주소에 값을 쓰려면 먼저 "이 주소를 어떤 타입의 포인터로 볼
것인가"를 알려 줘야 한다.

```c
*(uint64_t *) addr = value;
```

이 표현은 다음 두 단계를 합친 것이다.

1. `(uint64_t *) addr`: 정수형 주소값을 `uint64_t *`로 해석한다.
2. `*(uint64_t *) addr`: 그 포인터가 가리키는 저장 위치를 뜻한다.

대입까지 붙이면 "그 위치에 `uint64_t` 값 하나를 저장한다"는 의미가
된다.

```c
*(uint64_t *) addr = value;
```

즉 여기서 중요한 것은 주소를 더하거나 빼는 계산 자체가 아니라,
역참조된 표현식이 대입문의 왼쪽에 있다는 점이다.

## 주소 이동과 값 쓰기는 별개의 동작이다

주소를 이동하는 것과 값을 쓰는 것은 서로 다른 동작이다.

```c
addr -= sizeof (uint64_t);
*(uint64_t *) addr = value;
```

첫 줄은 `addr` 변수 안의 주소값을 바꾼다. 둘째 줄은 바뀐 `addr`이
가리키는 메모리 위치에 값을 쓴다.

stack에 값을 push하는 코드를 볼 때도 이렇게 나눠 읽으면 된다.

1. 저장할 위치를 정하기 위해 stack pointer 값을 조정한다.
2. 조정된 주소를 역참조해서 그 위치에 값을 저장한다.

두 줄이 붙어 있어서 하나의 작업처럼 보일 수 있지만, 개념적으로는
"주소값 변경"과 "역참조를 통한 메모리 쓰기"가 분리되어 있다.

## 포인터 값을 저장하는 경우

`argv` 배열처럼 포인터 값 자체를 메모리에 저장해야 할 때는, 저장할
칸을 "포인터가 들어가는 칸"으로 해석해야 한다.

```c
uintptr_t slot;
char *str_addr;

*(char **) slot = str_addr;
```

`slot`은 값을 저장할 메모리 위치의 주소다. `str_addr`은 문자열이
있는 위치의 주소다.

`*(char **) slot = str_addr`는 `slot`이 가리키는 메모리 위치에
`char *` 값 하나를 저장한다는 뜻이다. 문자열 bytes를 복사하는 것이
아니라, 문자열을 가리키는 주소값을 저장한다.

## 문자열 bytes를 저장하는 경우

문자열 자체는 포인터 하나가 아니라 여러 byte의 연속이다. 그래서
문자열 내용을 메모리에 저장할 때는 보통 byte 복사를 사용한다.

```c
uintptr_t dst;
const char *s = "hi";
size_t size = strlen (s) + 1;

memcpy ((void *) dst, s, size);
```

반면 문자열의 주소를 저장하는 것은 다음과 같이 포인터 값 하나를
저장하는 일이다.

```c
*(char **) slot = (char *) dst;
```

둘은 목적이 다르다.

| 목적 | 개념 |
|---|---|
| 문자열 bytes 저장 | `memcpy ((void *) dst, s, size)` |
| 포인터 값 저장 | `*(char **) slot = str_addr` |
| 정수 값 저장 | `*(uintptr_t *) slot = value` |

## 자주 헷갈리는 코드

### 메모리에 값을 쓰고 싶은데 주소 변수를 바꾸는 경우

```c
rsp = value;
```

이 코드는 `rsp`가 가리키는 메모리에 값을 쓰지 않는다. `rsp` 변수
자체의 값을 바꾼다.

메모리에 값을 쓰려면 역참조된 표현식이 대입문의 왼쪽에 있어야
한다.

```c
*(uintptr_t *) rsp = value;
```

### 포인터 배열처럼 읽고 싶은데 실제로는 문자열 blob인 경우

메모리에 문자열 bytes만 연속으로 들어 있다면:

```text
0x1000: "args-single\0onearg\0"
```

이 메모리를 곧바로 `char **` 배열처럼 보면 안 된다.

```c
((char **) 0x1000)[0]
```

위 코드는 `0x1000` 위치부터 포인터 값 하나를 읽으려고 한다. 하지만
실제로 그 위치에는 포인터가 아니라 문자 byte들이 들어 있다.

문자열 blob은 다음 문자열로 넘어갈 때 문자열 길이만큼 이동해야
한다.

```c
char *p = (char *) 0x1000;

/* 첫 문자열 */
p;

/* 다음 문자열 */
p += strlen (p) + 1;
```

반대로 `char **`처럼 접근하려면 메모리 앞부분에 실제 포인터 값들이
저장되어 있어야 한다.

```text
0x1000: 0x2000
0x1008: 0x2012
0x1010: NULL
0x2000: "args-single\0"
0x2012: "onearg\0"
```

이런 구조일 때만 `((char **) 0x1000)[0]`,
`((char **) 0x1000)[1]` 같은 해석이 맞다.

## 점검 질문

주소 관련 버그가 날 때는 다음 질문을 순서대로 확인한다.

1. 지금 바꾸려는 것이 주소값 변수인가, 그 주소가 가리키는 메모리인가?
2. 대입문의 왼쪽이 역참조된 표현식인가?
3. 이 주소를 어떤 타입의 포인터로 해석하고 있는가?
4. 그 타입의 값 하나는 몇 byte인가?
5. 문자열 bytes를 저장하는 것인가, 문자열의 주소를 저장하는 것인가?

이 다섯 가지가 정리되면 `rsp = value`와
`*(타입 *) rsp = value`를 구분하기 쉬워진다.
