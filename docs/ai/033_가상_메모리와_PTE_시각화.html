Intel x86-64 4-Level Paging, 4KB page 기준

가상 메모리와 PTE를 하나의 구조로 보기

가상 주소 변환은 OS가 만든 페이지 테이블을 CPU 내부의 MMU가 읽고, TLB가 결과를 캐싱하는 협업이다. 페이지 테이블은 추상적인 표가 아니라 RAM에 놓인 4KB 배열들의 트리이며, PTE는 그 배열 안의 64비트 정수다.

OS PTE를 만들고 정책을 결정한다. fault 처리와 TLB 무효화 책임도 OS에 있다.
MMU CR3에서 시작해 page walk를 수행하고 권한을 검사한다.
TLB 최근 변환 결과를 저장해 4단계 walk 비용을 줄인다.

Actors

OS, MMU, TLB의 책임 경계

핵심은 “OS가 만든다, MMU가 읽는다, TLB가 기억한다”이다. 정책은 OS에 있고, 변환 실행은 하드웨어에 있다.

PTE는 RAM 안의 값이므로 OS는 일반 load/store로 수정할 수 있다. 하지만 이미 TLB에 캐싱된 변환은 별도 무효화가 필요할 수 있다.

OS

software policy
  • 물리 메모리에서 page table page를 확보하고 PTE/PDE/PDPTE/PML4E를 작성한다.
  • PFN, Present, R/W, U/S, NX 같은 권한과 상태 필드를 결정한다.
  • 현재 주소 공간의 root를 CR3에 적재한다. 컨텍스트 스위치 때 바뀔 수 있다.
  • page fault, demand paging, swap, copy-on-write 같은 정책을 처리한다.
  • PTE를 바꾼 뒤 오래된 TLB 항목을 무효화한다. 멀티코어에서는 shootdown이 필요할 수 있다.

MMU

hardware walk
  • CPU 코어가 낸 가상 주소를 받아 TLB를 먼저 확인한다.
  • TLB miss면 CR3가 가리키는 PML4부터 page walk를 수행한다.
  • 각 단계의 Present와 권한 비트를 검사하고, 위반이면 page fault 예외를 발생시킨다.
  • Accessed/Dirty 비트는 필요할 때 0에서 1로 자동 설정할 수 있다.
  • OS 정책을 선택하지 않는다. frame 교체, 파일 로드, swap-in 결정은 OS의 일이다.

TLB

translation cache
  • 최근 가상 page에서 물리 frame으로의 변환 결과를 저장한다.
  • hit이면 4단계 메모리 접근을 생략하고 빠르게 물리 주소를 얻는다.
  • 권한 정보도 함께 캐싱될 수 있으므로 PTE 권한 변경 뒤 stale entry가 문제가 될 수 있다.
  • 주소 공간 전환, 특정 page unmap, 권한 축소 같은 상황에서 무효화가 필요하다.
  • TLB는 page table의 원본이 아니라 캐시다. 원본은 RAM 안의 page table이다.

Translation Pipeline

가상 주소 하나가 물리 주소가 되는 흐름

가상 주소 접근은 먼저 TLB에서 해결을 시도하고, 실패할 때만 page table tree를 따라간다.

page walk 중 어느 단계에서든 Present가 0이거나 권한이 맞지 않으면 변환 결과가 아니라 page fault가 나온다.

hit이면 page table을 읽지 않는다

TLB hit 경로에서는 page walk가 생략된다. 그래서 PTE를 바꾼 뒤 TLB 무효화를 빼먹으면, RAM의 PTE와 TLB의 캐시가 잠시 다른 의미를 가질 수 있다.

A/D 비트의 방향

하드웨어는 Accessed/Dirty를 0에서 1로 세울 수 있다. 1에서 0으로 지우거나 PFN, 권한, Present를 정책적으로 바꾸는 일은 OS가 한다.

fault는 실패만 뜻하지 않는다

Demand paging에서는 합법적인 접근도 처음에는 Present=0일 수 있다. OS가 frame을 준비하고 PTE를 채운 뒤 같은 명령을 다시 실행하게 한다.

4-Level Page Table

페이지 테이블은 4KB 배열들의 트리

4KB page 기준으로 각 table page는 512개 엔트리를 가진다. 가상 주소의 각 9비트 index가 그 512칸 중 하나를 고른다.

중간 엔트리는 다음 table page의 물리 주소를 가리키고, 마지막 PTE만 실제 data frame의 물리 주소를 가리킨다.

512칸 배열 strip으로 보는 메모리 값 흐름

각 행은 RAM에 놓인 4KB table page이고, 긴 막대는 그 안의 512개 8바이트 엔트리다. 색으로 강조된 칸이 현재 가상주소의 index가 고른 엔트리다.

D3.js로 그린 SVG 시각화다. 선택된 엔트리의 raw value를 주소 영역과 flags 영역으로 나누고, 그 주소 영역이 다음 table page 또는 data frame을 가리키는 흐름을 화살표로 표시한다.

PTE Anatomy

PTE는 PFN과 flags를 담은 64비트 정수

OS는 PTE를 메모리에 저장된 값으로 수정하고, MMU는 그 값을 CPU 규격대로 해석한다.

x86-64에서 실행 금지는 보통 NX bit로 표현된다. NX=1이면 execute가 금지되고, NX=0이면 다른 조건이 맞을 때 실행 가능하다.

PTE 값 조합해 보기

아래 PFN과 주요 flag로 개념적인 PTE 값을 만든다. 실제 CPU는 모델, mode, 보안 기능에 따라 더 많은 reserved/available bit를 가진다.

PFN이 본체다

PTE의 가장 중요한 정보는 이 가상 page가 어느 physical frame에 연결되는지다. 4KB 정렬이므로 하위 12비트는 주소가 아니라 flag로 쓸 수 있다.

Present=0의 의미

Present가 0이면 MMU는 유효한 변환으로 사용하지 않고 page fault를 발생시킨다. OS는 이 상태를 미매핑, swap out, lazy load 같은 정책 표현에 활용할 수 있다.

권한은 여러 단계에서 누적된다

최종 PTE만 보는 것이 아니라 상위 엔트리의 U/S, R/W, NX 계열 제약도 함께 영향을 준다. 어느 단계에서든 더 엄격한 제한이 있으면 접근이 막힐 수 있다.

Demand Paging

OS는 필요한 순간에 PTE를 채울 수 있다

모든 가상 주소의 PTE를 미리 만들 필요는 없다. 합법적인 영역이라도 처음 접근할 때 fault를 내고 그때 frame을 준비하는 방식이 흔하다.

합법성 판단에는 VMA, 파일 매핑, 익명 메모리, 스택 성장 규칙 같은 OS의 별도 메타데이터가 필요하다.

영역별 권한 예시

  • .text: read + execute, 보통 write 금지
  • .rodata: read only
  • .data, heap, stack: read + write
  • memory-mapped file: 매핑 옵션과 파일 권한에 따라 결정

COW도 같은 원리다

처음에는 read-only로 공유해 두고, write fault가 나면 OS가 새 frame을 복사해 PTE를 바꾼다. fault는 정책을 실행할 기회가 된다.

TLB까지 닫아야 끝난다

이미 캐시된 변환과 권한을 바꿀 때는 local invalidation 또는 다른 core에 대한 shootdown까지 고려해야 한다.

Metadata Cost

페이지 테이블 자체도 메모리를 쓴다

4KB page만으로 큰 연속 영역을 매핑하면, 지배적인 비용은 PT page들이다. PT page 하나는 512개 PTE로 2MB를 커버한다.

아래 계산은 4KB page만 사용하고, 매핑 시작 주소가 큰 경계에 정렬되어 있다고 보는 단순 모델이다. 실제 OS는 huge page, PCID, direct map 정책 등으로 달라질 수 있다.

4KB page 비용

PT page 비용은 대략 RAM / 512이다. 즉 64GB를 모두 4KB page로 매핑하면 PT page만 약 128MB가 든다.

2MB huge page

PDE 하나가 PT page를 가리키지 않고 2MB frame을 직접 가리킨다. 그래서 PT page 층을 생략할 수 있다.

자주 하는 혼동

PDE 하나는 2MB를 매핑한다. PD page 하나가 PDE 512개를 담기 때문에 전체로 1GB를 커버할 수 있는 것이다.

핵심만 다시 묶기

가상 메모리와 PTE를 이해할 때 가장 중요한 경계는 “누가 값을 만들고, 누가 해석하고, 어디에 캐싱되는가”이다.

페이지 테이블은 프로그램 데이터와 별개로 RAM을 차지하는 metadata이며, CPU가 이해하는 형식으로 OS가 만들어 둔 계층 구조다.
  • page table = RAM 안의 4KB 배열들이 이룬 트리. 각 배열은 uint64_t[512]처럼 볼 수 있다.
  • entry = 다음 table page 또는 data frame의 물리 base 주소와 flags를 합친 64비트 값이다.
  • OS = tree를 만들고 PTE 권한과 정책을 정한다. fault 처리와 TLB 무효화도 맡는다.
  • MMU = CR3에서 시작해 tree를 읽고, 권한 검사와 page fault 발생을 수행한다.
  • TLB = 변환 결과 캐시다. 원본이 아니므로 PTE 변경과 캐시 무효화를 구분해야 한다.
  • huge page = 더 높은 단계의 엔트리에서 walk를 멈추게 해 table 층과 metadata를 줄인다.
단일 HTML 문서. Mermaid.js, Chart.js, D3.js는 CDN으로 로드하며, 나머지 시각화와 상호작용은 inline CSS/JavaScript로 구성했다.
