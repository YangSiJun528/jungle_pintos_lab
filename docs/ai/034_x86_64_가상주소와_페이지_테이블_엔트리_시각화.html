Intel x86-64 4-level paging, 4KB page 기준

가상 주소는 저장값이 아니라 길 찾기 입력이다

48-bit 가상 주소를 64-bit page table entry 안에 저장하는 구조가 아니다. CPU는 가상 주소를 인덱스 묶음으로 쪼개고, 각 64-bit 엔트리에서는 다음 table page 또는 최종 physical frame의 base 주소와 flags를 읽는다.

Virtual Address 9/9/9/9/12 비트로 분해되어 각 table의 512칸 중 하나를 고르는 입력값
64-bit Entry 물리 주소의 정렬된 base 부분과 Present, R/W, U/S, NX 같은 flags

한 장으로 보는 핵심

왼쪽은 CPU가 가상 주소를 잘라 쓰는 방식이고, 오른쪽은 엔트리 하나가 담는 값이다.

Virtual Address Split

48-bit 가상 주소는 4개의 index와 offset으로 쪼개진다

Pintos KAIST reference와 로컬 pintos/include/threads/pte.h의 매크로는 같은 분해를 사용한다. PML4SHIFT=39, PDPESHIFT=30, PDXSHIFT=21, PTXSHIFT=12다.

각 9-bit index는 0부터 511까지다. 그래서 table page 하나는 uint64_t[512]처럼 볼 수 있고, 크기는 512 * 8 = 4096 bytes다.

64-bit Entry Decoder

엔트리는 physical base와 flags를 한 정수에 합친 값이다

4KB 정렬된 page table page와 page frame의 하위 12비트는 항상 0이다. 그래서 하위 12비트 공간을 주소 대신 flags로 쓴다.

로컬 Pintos는 PTE_ADDR(pte) = pte & ~0xFFF 형태로 주소 부분을 얻고, PTE_P, PTE_W, PTE_U, PTE_A, PTE_D 같은 flag 상수를 쓴다.
0이면 유효한 변환이 아니며 접근 시 page fault가 난다.
1이면 쓰기 가능, 0이면 read-only 성격이다.
1이면 user mode 접근 가능, 0이면 supervisor 전용이다.
하드웨어가 접근 시 1로 세울 수 있다.
쓰기 발생 시 1로 세울 수 있다. 주로 leaf entry에서 의미가 크다.
1이면 instruction fetch를 금지한다.

왜 하위 12비트를 비워 둘 수 있나

4KB

4096 = 2^12이므로 4KB 정렬 주소는 하위 12비트가 모두 0이다.

Base

엔트리에는 frame 또는 다음 table의 base 주소 상위 비트만 실질적으로 저장하면 된다.

Flags

비어 있는 하위 자리에는 Present, Writable, User, Accessed, Dirty 같은 속성이 들어간다.

Example

0x12345000 | 0x067 = 0x12345067이며, CPU는 다시 주소와 flags를 분리한다.

Flag Bits

하위 비트는 주소가 아니라 권한과 상태다

아래 표는 사용자가 제공한 정리와 x86-64 paging 설명을 학습용으로 압축한 것이다.

실제 reserved/available bit의 세부 의미는 CPU 기능과 paging mode에 따라 달라진다. Pintos 과제 코드에서 직접 쓰는 핵심 flag는 PTE_P, PTE_W, PTE_U, PTE_A, PTE_D다.
Bit 이름 핵심 의미 주의점
0 P, Present 엔트리가 유효한 변환을 제공하는지 표시한다. 0이면 page walk는 유효한 physical address 대신 page fault를 만든다.
1 R/W 쓰기 가능 여부를 나타낸다. 상위 레벨의 더 엄격한 제한과 함께 적용된다.
2 U/S user mode 접근 허용 여부를 나타낸다. 0이면 supervisor 영역 성격이다.
3, 4 PWT, PCD 캐시 정책 관련 비트다. PAT와 함께 메모리 타입 선택에 쓰일 수 있다.
5 A, Accessed 읽기, 쓰기, 실행 접근이 있었는지 하드웨어가 표시할 수 있다. OS는 page replacement 근사에 활용할 수 있고, 직접 0으로 지울 수 있다.
6 D, Dirty 쓰기 발생 여부를 나타낸다. PTE와 large-page leaf entry에서 특히 중요하다.
7 PS 또는 PAT PDPTE/PDE에서는 huge page 여부, PTE에서는 PAT 비트로 쓰인다. PDPTE의 PS=1은 1GB page, PDE의 PS=1은 2MB page를 뜻한다.
8 G, Global 특정 조건에서 TLB 항목을 주소 공간 전환 후에도 유지할 수 있다. 커널 공통 mapping에 쓰이는 개념이다.
9..11 AVL OS가 사용할 수 있는 available bit 영역이다. Pintos의 PTE_AVL도 이 범위를 가리킨다.
63 XD/NX 1이면 해당 page에서 instruction fetch를 금지한다. CPU 설정에 따라 활성화되어야 의미가 있다.

4KB, 2MB, 1GB Pages

페이지가 커지면 주소 필드 시작 bit도 올라간다

4KB page는 offset이 12비트라서 physical address field가 bit 12부터 시작한다. 2MB page는 offset이 21비트, 1GB page는 offset이 30비트이므로 leaf entry의 주소 필드도 각각 bit 21, bit 30부터 시작한다.

PDPTE/PDE에서 PS=0이면 다음 table로 내려간다. PS=1이면 그 엔트리가 leaf처럼 동작해 huge page frame을 직접 가리킨다.

Sparse Address Space

상위 엔트리 하나가 비어 있으면 하위 512갈래를 만들 필요가 없다

48-bit 가상 주소 공간은 256TB로 크다. 모든 page에 대해 PTE를 미리 만들면 낭비가 크므로, 계층 구조는 실제로 쓰는 영역의 하위 table page만 할당하게 해 준다.

Pintos reference도 page table은 CPU가 page를 frame으로 변환하는 자료구조이며, project 3에서는 fault 시 supplemental page table을 함께 확인한다고 설명한다.

압축 정리

  • 가상 주소는 page table entry에 저장되는 값이 아니다.
  • 가상 주소의 index들이 각 table page의 512개 entry 중 하나를 선택한다.
  • 중간 entry는 다음 table page의 physical base를 저장한다.
  • 최종 PTE는 4KB physical frame base와 flags를 저장한다.
  • 4KB 정렬 때문에 하위 12비트는 flags로 재활용할 수 있다.
  • Present=0인 상위 entry는 큰 미사용 영역을 한 번에 표현한다.
