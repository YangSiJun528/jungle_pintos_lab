# 주소 변수와 메모리 쓰기

이 문서는 C에서 "주소 변수 자체를 바꾸는 것"과 "그 주소가 가리키는 메모리에 값을 쓰는 것"의 차이를 정리한다. Pintos `argument passing`을 구현할 때 `rsp` 같은 주소값을 다루다 보면 이 둘이 쉽게 섞인다.

## 한 줄 결론

`rsp = value`는 `rsp`라는 변수의 값을 바꾸는 것이다.

`*(타입 *) rsp = value`는 `rsp`가 가리키는 메모리 위치에 `value`를 저장하는 것이다.

## 주소 변수와 메모리 칸

다음과 같은 상태를 생각하자.

```text
주소 변수:
  rsp = 1000

메모리:
  1000: ?
  1008: ?
  1016: ?
```

여기서 `rsp`는 메모리 주소를 담고 있는 변수다. `rsp` 안에 들어 있는 값은 `1000`이다.

중요한 점은 `rsp`와 `1000번지 메모리`가 같은 것이 아니라는 점이다.

- `rsp`: 주소값을 담은 변수
- `1000번지 메모리`: `rsp`가 가리키는 실제 저장 위치

## `rsp = 0`의 의미

다음 코드는 메모리 `1000`번지에 `0`을 저장하지 않는다.

```c
rsp = 0;
```

결과는 다음과 같다.

```text
주소 변수:
  rsp = 0

메모리:
  1000: ?
  1008: ?
  1016: ?
```

즉 `rsp`가 더 이상 `1000`을 가리키지 않고, 주소 `0`을 가리키게 된다.

## `*(uintptr_t *) rsp = 0`의 의미

다음 코드는 `rsp`가 가리키는 메모리 위치에 `0`을 저장한다.

```c
*(uintptr_t *) rsp = 0;
```

`rsp`가 `1000`을 담고 있었다면 결과는 다음과 같다.

```text
주소 변수:
  rsp = 1000

메모리:
  1000: 0
  1008: ?
  1016: ?
```

여기서 `rsp` 값은 바뀌지 않는다. 바뀐 것은 `1000`번지의 메모리 내용이다.

## 0, 1, 2를 차례로 저장하는 예시

64-bit 환경에서 `uintptr_t`는 보통 8 byte다. 따라서 `uintptr_t` 값을 연속으로 저장하면 주소가 8씩 이동한다고 생각할 수 있다.

```c
uintptr_t rsp = 1000;

*(uintptr_t *) rsp = 0;

rsp += sizeof (uintptr_t);
*(uintptr_t *) rsp = 1;

rsp += sizeof (uintptr_t);
*(uintptr_t *) rsp = 2;
```

결과는 다음과 같다.

```text
주소 변수:
  rsp = 1016

메모리:
  1000: 0
  1008: 1
  1016: 2
```

이 예시에서 마지막 `rsp`는 `1016`이다. 마지막으로 쓴 값이 `2`이기 때문이 아니라, 값을 쓸 때마다 `rsp`를 8씩 이동시켰기 때문이다.

## stack처럼 아래로 자라는 경우

stack은 보통 높은 주소에서 낮은 주소 방향으로 자란다. 그래서 값을 push한다는 것은 보통 다음 순서로 생각한다.

1. `rsp`를 저장할 크기만큼 낮춘다.
2. 낮춘 `rsp`가 가리키는 위치에 값을 쓴다.

개념 예시는 다음과 같다.

```c
uintptr_t rsp = 1024;

rsp -= sizeof (uintptr_t);
*(uintptr_t *) rsp = 2;

rsp -= sizeof (uintptr_t);
*(uintptr_t *) rsp = 1;

rsp -= sizeof (uintptr_t);
*(uintptr_t *) rsp = 0;
```

결과는 다음과 같다.

```text
주소 변수:
  rsp = 1000

메모리:
  1000: 0
  1008: 1
  1016: 2
```

위쪽 예시와 최종 메모리 모양은 같지만, 주소를 이동하는 방향이 다르다.

## 포인터 값을 저장하는 경우

`argv` 배열처럼 포인터 값을 저장해야 할 때는 "문자열 자체"가 아니라 "문자열이 있는 주소"를 저장한다.

예를 들어 어떤 문자열이 주소 `2000`에 있다고 하자.

```text
메모리:
  2000: 'h'
  2001: 'i'
  2002: '\0'
```

이 문자열의 주소를 `1000`번지에 저장하고 싶으면 다음처럼 생각한다.

```c
uintptr_t rsp = 1000;
char *str_addr = (char *) 2000;

*(char **) rsp = str_addr;
```

결과는 다음과 같다.

```text
주소 변수:
  rsp = 1000

메모리:
  1000: 2000
  2000: "hi\0"
```

`*(char **) rsp`라고 쓰는 이유는 `rsp` 위치의 메모리를 `char *` 하나가 들어가는 칸으로 해석하겠다는 뜻이다.

## 문자열을 저장하는 경우

문자열은 포인터 하나가 아니라 여러 byte의 연속이다. 그래서 `*` 대입 하나로 저장하지 않고 byte 복사를 사용한다.

```c
uintptr_t rsp = 1000;
const char *s = "hi";
size_t size = strlen (s) + 1;

memcpy ((void *) rsp, s, size);
```

결과는 다음과 같다.

```text
주소 변수:
  rsp = 1000

메모리:
  1000: 'h'
  1001: 'i'
  1002: '\0'
```

문자열을 저장하는 것과 문자열 주소를 저장하는 것은 다르다.

| 목적 | 개념 |
|---|---|
| 문자열 bytes 저장 | `memcpy((void *) addr, string, len)` |
| 포인터 값 저장 | `*(char **) addr = string_address` |
| 정수 값 저장 | `*(uintptr_t *) addr = value` |

## 자주 헷갈리는 코드

### 메모리에 0을 쓰고 싶은데 주소 변수를 0으로 바꾸는 경우

```c
rsp = 0;
```

이 코드는 메모리에 `0`을 쓰지 않는다. `rsp` 자체를 `0`으로 바꾼다.

메모리에 `0`을 쓰려면 다음처럼 "역참조"가 필요하다.

```c
*(uintptr_t *) rsp = 0;
```

### 포인터 배열처럼 읽고 싶은데 실제로는 문자열 blob인 경우

메모리가 다음처럼 문자열만 연속으로 들어 있다면:

```text
1000: "args-single\0onearg\0"
```

이 메모리를 곧바로 `char **` 배열처럼 보면 안 된다.

```c
((char **) 1000)[0]
```

위 코드는 `1000`번지부터 8 byte를 포인터 값으로 해석한다. 하지만 실제로 그 위치에는 포인터가 아니라 문자 `'a'`, `'r'`, `'g'`, `'s'`, ...가 들어 있다.

문자열 blob은 다음 문자열로 넘어갈 때 `strlen(p) + 1`만큼 이동해야 한다.

```c
char *p = (char *) 1000;

/* 첫 문자열 */
p;

/* 다음 문자열 */
p += strlen (p) + 1;
```

반대로 `char **`처럼 접근하려면 메모리 앞부분에 실제 포인터 값들이 저장되어 있어야 한다.

```text
1000: 2000
1008: 2012
1016: 0
2000: "args-single\0"
2012: "onearg\0"
```

이런 구조일 때만 `((char **) 1000)[0]`, `((char **) 1000)[1]` 같은 해석이 맞다.

## 점검 질문

주소 관련 버그가 날 때는 다음 질문을 순서대로 확인한다.

1. 지금 바꾸려는 것이 주소 변수인가, 그 주소가 가리키는 메모리인가?
2. `=` 왼쪽에 `*`가 있는가?
3. 이 주소에 저장하려는 값의 크기는 몇 byte인가?
4. 이 메모리 위치를 어떤 타입의 칸으로 해석하고 있는가?
5. 문자열 bytes를 저장하는 것인가, 문자열의 주소를 저장하는 것인가?

이 다섯 가지가 정리되면 `rsp = value`와 `*(타입 *) rsp = value`를 구분하기 쉬워진다.
