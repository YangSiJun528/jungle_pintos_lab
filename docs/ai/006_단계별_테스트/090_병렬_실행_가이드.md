# 병렬 실행 가이드

이 문서는 단계별 테스트를 병렬로 돌릴 때 안전한 범위와 피해야 할 범위를 정리한다. 모든 명령은 Docker 컨테이너 안에서 실행한다.

## 기본 원칙

- `userprog`, `vm`, `filesys/base`는 같은 build 디렉터리에서 `make -j"$(nproc)" ...result` 예시를 사용할 수 있다.
- `filesys/extended`, `filesys/buffer-cache`는 같은 build 디렉터리에서 `tmp.dsk`를 공유하므로 안전한 병렬 대상으로 보지 않는다.
- `filesys/extended`를 병렬로 나누려면 `/tmp`에 Pintos 작업 복사본을 여러 개 만들고 각 복사본에서 분리 실행한다.
- 병렬 실행 전에는 각 작업 디렉터리에서 `make clean`을 실행해 stale result를 지운다.

## 공통 준비

```bash
export PINTOS_ROOT=/workspace/pintos
source "$PINTOS_ROOT/activate"
```

## userprog 병렬 예시

```bash
make -C "$PINTOS_ROOT/userprog" clean
make -j"$(nproc)" -C "$PINTOS_ROOT/userprog" \
  build/tests/userprog/args-none.result \
  build/tests/userprog/args-single.result \
  build/tests/userprog/create-normal.result \
  build/tests/userprog/open-normal.result \
  build/tests/userprog/read-normal.result \
  build/tests/userprog/write-normal.result \
  build/tests/userprog/exec-once.result \
  build/tests/userprog/wait-simple.result
```

## filesys/extended 병렬 분리 예시

같은 `$PINTOS_ROOT/filesys/build`에서 `filesys/extended` target을 `make -j`로 섞지 않는다. 아래처럼 `/tmp`에 복사본을 만든 뒤 각 복사본에서 한 그룹씩 실행한다.

```bash
RUN_ROOT="/tmp/pintos-filesys-parallel-$(date +%s)"
mkdir -p "$RUN_ROOT"
cp -a "$PINTOS_ROOT" "$RUN_ROOT/grow"
cp -a "$PINTOS_ROOT" "$RUN_ROOT/dir"
cp -a "$PINTOS_ROOT" "$RUN_ROOT/symlink"
```

각 복사본을 background job으로 실행한다.

```bash
(
  export PINTOS_ROOT="$RUN_ROOT/grow"
  source "$PINTOS_ROOT/activate"
  make -C "$PINTOS_ROOT/filesys" clean
  make -C "$PINTOS_ROOT/filesys" \
    build/tests/filesys/extended/grow-create.result \
    build/tests/filesys/extended/grow-seq-sm.result \
    build/tests/filesys/extended/grow-seq-lg.result \
    build/tests/filesys/extended/grow-sparse.result
) &

(
  export PINTOS_ROOT="$RUN_ROOT/dir"
  source "$PINTOS_ROOT/activate"
  make -C "$PINTOS_ROOT/filesys" clean
  make -C "$PINTOS_ROOT/filesys" \
    build/tests/filesys/extended/dir-mkdir.result \
    build/tests/filesys/extended/dir-mk-tree.result \
    build/tests/filesys/extended/dir-rmdir.result \
    build/tests/filesys/extended/dir-rm-tree.result
) &

(
  export PINTOS_ROOT="$RUN_ROOT/symlink"
  source "$PINTOS_ROOT/activate"
  make -C "$PINTOS_ROOT/filesys" clean
  make -C "$PINTOS_ROOT/filesys" \
    build/tests/filesys/extended/symlink-file.result \
    build/tests/filesys/extended/symlink-dir.result \
    build/tests/filesys/extended/symlink-link.result \
    build/tests/filesys/extended/syn-rw.result
) &

wait
```

## 피해야 할 실행

아래처럼 같은 `filesys/build`에서 extended target을 섞어 `make -j`로 실행하지 않는다.

```bash
make -j"$(nproc)" -C "$PINTOS_ROOT/filesys" \
  build/tests/filesys/extended/grow-create.result \
  build/tests/filesys/extended/dir-mkdir.result \
  build/tests/filesys/extended/symlink-file.result
```

## 실패 시 확인할 포인트

- 병렬 실행에서만 실패하면 먼저 같은 target을 순차 실행해 재현성을 확인한다.
- `filesys/extended` 병렬 실패는 공유 `tmp.dsk` 충돌인지 확인한다.
- 각 복사본의 `PINTOS_ROOT`가 서로 다른 경로를 가리키는지 확인한다.
- background job 중 하나가 compile failure로 끝났는지 `.errors`를 확인한다.
- 성능 문제와 correctness 문제를 분리하기 위해 작은 테스트 묶음부터 병렬화한다.
